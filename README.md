# n6k server

Define data in Python and serve it over the native n6k protocol (the `n6k_server` driver), with React page serving.

## Prerequisites

- Python 3.12+
- [uv](https://docs.astral.sh/uv/)
- [Bun](https://bun.sh/)

## Install

```bash
uv sync
```

## Quick start

### 1. Initialize the UI

```bash
uv run n6k init demo.app:app
```

This will:
- Create the `ui/` directory with scaffolding (tailwind, esbuild, shadcn config)
- Install JS dependencies via `bun install`
- Import your app to discover `page()` calls and write `page.tsx` files
- Detect required shadcn components and prompt to install them

### 2. Run the server

```bash
uv run uvicorn demo.app:app --reload
```

### 3. Visit

- `http://localhost:8000/` — simple page
- `http://localhost:8000/form` — page with shadcn components
- data: attach with `ATTACH 'n6k://localhost:8000/index' AS page (TYPE n6k);` then `SELECT * FROM page.main.demo;`

To run a single Python file as a database server (no frontend):

```bash
uv run n6k database path/to/data.py        # add --reload to reload on edits
```

## Usage

### Data sources

```python
import pandas as pd
from n6k_app import Database

db = Database()              # in a data.py: mounts at /<page-slug>

@db.data()                   # → table  page.main.my_table
def my_table():
    return pd.DataFrame({"id": [1, 2, 3]})
```

Served over the native n6k protocol (the `n6k_server` driver). A database is
selected by the **URL path** it mounts at; the `AS <alias>` is a free client-side
label that the server adopts as its catalog name. Attach from any `TYPE n6k`
client and query it as a DuckDB table:

```sql
ATTACH 'n6k://localhost:8000/<prefix>' AS page (TYPE n6k);
SELECT * FROM page.main.my_table;
```

### Actions

```python
from typing import Annotated
from n6k_app import Session, action

@action
def add_todo(title: str, session: Annotated[Session, db]) -> int:
    """Add a todo and return its id."""
    ...
```

An action is a JSON-RPC method on the socket of every page whose `data.py` binds it
(`/<slug>/ws`), and an MCP tool; its docstring and type hints are the tool schema. It
belongs to no database: members it imports resolve against the page's databases.
`Annotated[Session, db]` and `Annotated[<native Connection>, db]` are injected for that
database and hidden from callers; a bare `Session` / `Connection` means the page's only
database. From the page:

```ts
const id = await registered.rpc.call("add_todo", { title: "milk" });
```

A page with a `page.py` also answers `render({ state })` with its component tree.

Every page also serves the MCP tool `show_page(state?)`: the component tree for a `page.py`,
the source for a `page.mdx` / `page.tsx`.

### Pages

```python
from n6k_app.app import create_app, page

app = create_app()

page(app, "/", "<div>Hello</div>")

page(app, "/dashboard", """
    <div className="flex gap-2 p-8">
      <Button>Click me</Button>
    </div>
""")
```

Pages are JSX snippets. shadcn components (`<Button>`, `<Checkbox>`, etc.) are auto-detected and imported at build time.

On first request, all pages are bundled together via esbuild with code splitting — shared dependencies (React, Radix, etc.) are extracted into chunks.

### Adding components

After adding new shadcn components to your pages, re-run init to install them:

```bash
uv run n6k init demo.app:app
```

Or add them directly:

```bash
bun run --cwd ui shadcn add button card dialog
```

## Project structure

```
src/n6k_app/       # library source
demo/app.py           # example application
ui/                   # generated by `n6k init`
  pages/              # page.tsx / page.mdx files (written by page() calls)
  components/ui/      # shadcn components (installed via shadcn CLI)
  build/              # esbuild output (generated on first request)
  build.mjs           # esbuild config with n6k plugin
  globals.css         # tailwind + design tokens
  lib/utils.ts        # cn() utility
tests/
```
